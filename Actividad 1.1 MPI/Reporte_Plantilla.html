Descripción del objetivo

El objetivo de la práctica es implementar un modelo de programación paralela híbrida en C++. Se utiliza MPI como el mecanismo principal para distribuir la ejecución del llenado de un arreglo entre diferentes procesos distribuidos en múltiples nodos. Al mismo tiempo, se emplea OpenMP para aprovechar todos los recursos de procesamiento interno de cada nodo, logrando paralelizar el trabajo local en múltiples hilos.

Explicación de la implementación de MPI y OpenMP

MPI (Message Passing Interface): Se implementaron las funciones MPI_Init para iniciar el entorno, MPI_Comm_rank para identificar el número de proceso actual y MPI_Comm_size para saber cuántos procesos en total se están ejecutando. El proceso principal calcula la carga de trabajo y mediante un broadcast (MPI_Bcast) distribuye el tamaño del problema. Finalmente, se cierra el entorno mediante MPI_Finalize. Se utiliza MPI_Barrier para evitar que la impresión de texto en la terminal se traslape entre procesos.

OpenMP: Se encapsuló la lógica de llenado del arreglo dentro de una clase llamada ProcesadorArreglo. Se declara una región paralela mediante #pragma omp parallel y se distribuye el bucle de llenado mediante #pragma omp for. Para calcular de forma segura el porcentaje de avance, se utilizó #pragma omp atomic capture sobre un contador compartido de elementos llenados, lo que previno condiciones de carrera. Además, se usó #pragma omp critical al momento de imprimir el progreso del 10% al 100%.

Descripción de las funciones utilizadas y arreglos dinámicos

El programa utiliza POO (Programación Orientada a Objetos) mediante la clase ProcesadorArreglo. El almacenamiento de memoria se resolvió de forma estricta reservando un bloque en el Heap mediante arreglo = new int[N_local] en el constructor, y liberándolo utilizando delete[] arreglo en el destructor, respetando la regla de no utilizar vector u otras estructuras preconstruidas.

Generación de valores aleatorios

Para evitar secuencias repetidas, en lugar de un generador estándar dependiente del proceso, se aplicó un LCG (Generador Congruencial Lineal) interno, inicializado utilizando una operación XOR entre el tiempo actual time(NULL), el identificador del proceso (rank) y el número del hilo (omp_get_thread_num()). De esta manera, cada hilo de cada proceso produce datos puramente aleatorios desde 0 a 999.

Explicación del porcentaje de avance

Se programó una lógica de umbrales condicionales. Conforme el arreglo local (N_local) se llena, se calcula el porcentaje mediante la fórmula matemática convencional. Solo cuando dicho porcentaje sobrepasa una barrera múltiplo de 10%, el sistema entra en una zona de impresión y lanza el mensaje a la consola, asegurando explícitamente mostrar: el porcentaje, el ID del proceso, el nombre de la máquina y el hilo de OpenMP en ejecución.
